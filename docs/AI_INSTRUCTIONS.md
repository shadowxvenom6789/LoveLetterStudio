# AI Development Instructions

These instructions apply to every development task.

Read this file before modifying any project files.

---

# Primary Objective

Continue developing the existing project.

Never rebuild it.

Never restart it.

Always extend it.

---

# Before Starting Any Task

Read the following files in this order:

1. AI_CONTEXT.md

2. CURRENT_STATE.yaml

3. RULES.md

4. TASKS.md

5. ARCHITECTURE.md (only if needed)

Do not read unnecessary files.

---

# Development Workflow

Understand the requested task.

Identify which module owns the feature.

Modify only the required files.

Preserve all existing functionality.

Test for possible side effects.

Update project documentation if necessary.

---

# Modification Rules

Never modify unrelated code.

Never rename files unless requested.

Never delete existing functionality.

Never replace working systems.

Never change architecture without approval.

Always preserve backward compatibility.

---

# Coding Standards

Write modular code.

Prefer reusable functions.

Avoid duplicate logic.

Use meaningful variable names.

Keep functions focused.

Keep code readable.

Avoid unnecessary dependencies.

---

JavaScript

Logic and interaction only.

# Responses

Return only modified files.

Do not regenerate unchanged files.

Explain changes briefly.

Do not include unnecessary explanations.

---

# Documentation

If a feature is completed:

Update CURRENT_STATE.yaml

Update CHANGELOG.md

Update TASKS.md

Only update documentation that actually changed.

---

# Architecture

Extend existing modules.

Do not duplicate systems.

Create new modules only when necessary.

Keep dependencies minimal.

---

# Performance

Avoid unnecessary DOM updates.

Avoid unnecessary re-rendering.

Keep animations smooth.

Optimize only when useful.

---

# UI

Preserve design language.

Preserve responsiveness.

Preserve animations.

Improve instead of replacing.

---

# Error Handling

Handle invalid input gracefully.

Avoid crashes.

Provide useful messages.

Fail safely.

# When Unsure

Ask for clarification.

Never make large assumptions.

Create a professional, maintainable, modular application that can continue growing without major rewrites.
