# Development Rules

These rules apply to every task unless the user explicitly overrides them.

---

# General Rules

Always build on the existing project.

Extend existing functionality instead of replacing it.

Preserve backward compatibility whenever possible.

Never remove working features unless specifically requested.

Never redesign the application unless explicitly requested.

Never change project goals.

---

# Code Rules

Write clean, readable, modular code.

Prefer reusable functions.

Avoid duplicated code.

Keep files organized.

Use meaningful variable names.

Comment only where necessary.

Avoid unnecessary complexity.

Optimize only when requested.

---

# File Rules

Never rename existing files without permission.

Never move files unless required.

Never delete files.

Only modify files required for the current task.

If new files are needed, place them in the correct folder.

---

# UI Rules

Keep the existing visual identity.

Preserve animations.

Preserve responsiveness.

Maintain smooth transitions.

Do not replace the design language.

Keep layouts clean and modern.

---

# Animation Rules

Animations should feel natural.

Prefer smooth easing.

Avoid sudden movement.

Avoid excessive effects.

Performance is more important than visual complexity.

---

# Feature Rules

Implement only the requested feature.

Do not add unrelated improvements.

Do not remove existing behavior.

Do not silently rewrite working systems.

If a better architecture is required, explain why first.

---

# Documentation Rules

Update CURRENT_STATE.md after completing a task.

Update CHANGELOG.md when features are added.

Mark completed tasks inside TASKS.md.

Keep documentation synchronized with the project.

---

# AI Behavior

Assume this project is under active development.

Continue the existing architecture.

Never restart the project from scratch.

Never replace Python with another backend.

Never introduce frameworks unless requested.

Never make large structural changes without approval.

When uncertain, ask before changing architecture.

---

# Response Rules

Return only modified files.

Do not rewrite unchanged files.

Briefly explain what changed.

Keep responses focused.

Avoid unnecessary explanations.

---

# Priority Order

1. Preserve functionality

2. Maintain compatibility

3. Keep code clean

4. Keep performance high

5. Improve maintainability

6. Add requested feature

7. Optimize if appropriate

---

Following these rules is more important than writing shorter or more clever code.
